# Bitácora de uso de IA

Registro resumido de las decisiones principales tomadas con ayuda de IA. Se conservaron las reglas del PDF, se revisaron las propuestas y se modificó el código para que el responsable pueda explicarlo.

| # | Herramienta | Qué pediste (prompt resumido) | Qué te dio | Qué estaba mal o cambiaste | Por qué |
| --- | --- | --- | --- | --- | --- |
| 1 | ChatGPT / Codex | Diseñar el esquema del MVP de ventas en Laravel 12. | Migraciones para usuarios, sucursales, categorías, productos, ventas, partidas e inventario. | Se sustituyeron tipos flotantes por `DECIMAL(12,2)`, se agregaron FKs e índices y se guardó el costo histórico por partida. | Evitar errores de redondeo y mantener referencias e informes históricos confiables. |
| 2 | ChatGPT / Codex | Implementar login API para React con validaciones y cierre de sesión seguro. | Login con Sanctum, validación de credenciales, token y logout. | Se añadió límite de cinco intentos por minuto, respuesta uniforme ante credenciales incorrectas y revocación del token actual. | Cumplir la regla de seguridad del PDF y no revelar si existe un correo. |
| 3 | ChatGPT / Codex | Definir permisos para admin y vendedor y aplicarlos en backend. | Tablas de roles, permisos y relación muchos a muchos. | Se añadieron comprobaciones de sucursal y `sales.view_own` limita historial/detalle del vendedor a sus ventas; la autorización se aplica en API. | No depender de botones ocultos para proteger los datos. |
| 4 | ChatGPT / Codex | Generar datos de prueba realistas con Faker y seeders repetibles. | Seeders para catálogos, usuarios, inventarios y 2,500 ventas. | Se fijó locale `es_MX`, montos por centavos, lotes y `upsert`/`updateOrCreate`; diciembre tiene mayor ponderación y una sucursal menor volumen. | Cumplir cantidades/patrones del PDF y repetir el seeding sin duplicar datos. |
| 5 | ChatGPT / Codex | Preparar catálogo y SKU para el punto de venta del boceto. | Productos distribuidos entre ocho categorías y SKU únicos. | Se alinearon categorías y nombres con ferretería; los SKU usan Faker `unique()->bothify()` con prefijo por categoría. Se preserva el ID de los productos semilla al actualizar el esquema previo. | Hacer que catálogo, boceto y reportes usen el mismo dominio, manteniendo FKs e idempotencia. |
| 6 | ChatGPT / Codex | Crear ventas con stock y totales calculados desde el servidor. | Servicio de ventas con transacción, consulta de productos y descuento de existencias. | Se añadió bloqueo de filas, cálculo en centavos, IVA 16 %, snapshot de costo y rechazo total si falta stock. | Evitar precios manipulados por cliente y ventas parciales en concurrencia. |
| 7 | ChatGPT / Codex | Construir reportes con filtros y datos suficientes para el dashboard. | Servicio de agregación, matriz por sucursal/categoría y CSV. | Se aplicaron filtros SQL por fechas/sucursal y estado pagada; se documentó la diferencia entre importes con IVA y netos. | No cargar miles de ventas al navegador y excluir cancelaciones de todas las métricas. |
| 8 | ChatGPT / Codex | Integrar un asistente local de Ollama para preguntas de reportes. | Servicio Laravel que envía contexto agregado y recibe JSON estructurado. | Se prohibió SQL y acceso a tablas crudas; se quitaron IDs, se clasifican temas y se valida/normaliza JSON. La respuesta inválida no se devuelve al cliente. | Proteger información, limitar la IA a VentasLite y mantener errores controlados para React. |
| 9 | ChatGPT / Codex | Probar módulos y corregir fallas reportadas en PHPUnit/Pest. | Pruebas Feature para auth, catálogo, permisos, ventas, cancelaciones, reportes y asistente. | Se corrigieron fixtures de fechas/tipos, se alinearon aserciones al prompt y se agregaron casos de aislamiento del vendedor, consultas multi-tema y salida JSON con code fence. | Verificar autorización, consistencia y formato con evidencia automatizada. |
| 10 | Qwen3:4b local + ChatGPT / Codex | Contestar qué sucursal tuvo menos ventas entre el 25/08/2026 y el 25/11/2026. | Ollama respondió Querétaro con `140,064.81 MXN` y el rango de fechas. | Una consulta multitema devolvió `OLLAMA_INVALID_RESPONSE`; se amplió el presupuesto de salida y se añadió normalización segura para JSON rodeado de texto/code fences. Esa corrección aún debe probarse con Ollama real. | Registrar la diferencia entre pruebas simuladas y la llamada local, y validar el formato antes del frontend. |
| 11 | ChatGPT / Codex | Diferenciar preguntas válidas de rendimiento agregado frente a solicitudes de datos personales; preparar Groq solo para producción. | Reglas explícitas para ranking de vendedores/productos, fechas y ausencia de ventas; proveedor configurable Groq/Ollama. | La lógica numérica de umbrales y extremos se calcula en Laravel; domicilio/contacto se rechaza antes de enviar contexto. Ollama continúa como proveedor local; Groq requiere una llave secreta en el hosting. | Dar respuestas basadas en datos reales sin revelar información privada ni acoplar desarrollo local a una API externa. |

| 12 | ChatGPT / Codex | Completar el punto de caché de reportes antes de iniciar el frontend. | Caché del dashboard con filtros por periodo/sucursal e invalidación posterior al registro o cancelación de ventas. | Se usa una versión de caché para invalidar sin tags; si el store falla, el reporte se recalcula directamente. Se deja la llave de Groq vacía en `.env.example`. | Reducir agregaciones repetidas sin servir métricas antiguas tras cambios de ventas ni incluir secretos en archivos versionados. |

| 13 | ChatGPT / Codex | Eliminar respuestas analíticas hardcodeadas y dejar que el modelo interprete la pregunta con base en los reportes. | El asistente envía un conjunto compacto de todos los agregados, sin clasificación de intención ni respuestas especiales para umbrales, vendedores, fechas o periodos sin ventas. | Laravel conserva permisos, filtros, cálculo de métricas, validación de salida y el bloqueo de privacidad como control de seguridad. Se actualizó la prueba para verificar que preguntas de ranking, umbral, mes y periodo vacío lleguen al modelo. | Evitar una lista creciente de reglas y conservar los límites de seguridad y exactitud de datos en el backend. |

| 14 | ChatGPT / Codex | Corregir el test que falló después de quitar respuestas analíticas fijas. | La petición al LLM ya estaba ocurriendo; la prueba comparaba una frase literal del prompt anterior. | Se alineó la aserción con la frase actual que define el alcance del asistente. El usuario debe volver a ejecutar el filtro. | Evitar que un cambio legítimo de redacción del prompt produzca una falla falsa de comportamiento. |
| 15 | ChatGPT / Codex | Pulir una respuesta real donde una pregunta de productos/fecha recibió una explicación de margen con categorías inventadas. | El caso mostró que Qwen3:4b no priorizó la tarea ni verificó entidades contra el contexto. | Se añadió una secuencia general de análisis: tema, periodo, sección pertinente y comprobación de evidencias; los contextos de productos tienen nombres explícitos para top por unidades e importe. Temperatura bajó a 0.1 y el contexto Ollama se amplió a 8,192 tokens configurables para acomodar datos e instrucciones. Aún debe validarse con Ollama real. | Mejorar seguimiento de instrucciones sin crear una tabla de preguntas/respuestas ni permitir datos inventados. |

## Alcance de las pruebas

El usuario reportó `ReportAssistantTest` aprobado con 10 pruebas y 29 aserciones antes de la refactorización que eliminó respuestas fijas. La suite se actualizó para comprobar que el modelo reciba todos los agregados y que preguntas de ranking, umbral, fechas y periodo vacío lleguen a Ollama; queda pendiente de ejecución. Groq real tampoco se ha verificado y requiere una llave configurada como secreto del hosting. El despliegue de React se documentará cuando exista ese frontend.
